# Поиск логов

Справочник параметров клиента: фильтры, временные окна, вывод и обработка ошибок.
Подключение и отзыв доступа описаны в [README](../README.md).

## Фильтры

В CLI `--filters` принимает **сам объект фильтров**, без оболочки `filters`.
`--filters-file path.json` принимает тот же объект из UTF-8 файла.
Если обе временные границы отсутствуют, клиент подставляет последние 15 минут
или `--minutes N`. Если задана одна граница, нужно указать и вторую.

### Допустимые поля

Все заполненные группы соединяются через AND. Значения внутри точного списка
работают как OR. Неизвестные поля и неизвестные ключи в maps отклоняются.

| Поля | Тип и смысл |
| --- | --- |
| `sinceMs`, `untilMs` | Обязательные неотрицательные целые миллисекунды Unix; обе границы включительные, `untilMs > sinceMs`. |
| `search` | Строка поиска без учёта регистра по `msg`, `error_message`, `handler_url`, `url`, `job_type`, `trace_id`. |
| `msgMode` | `contains` (по умолчанию), `starts` или `exact`. Последние два режима ищут только по `msg`; `exact` использует точное сравнение. |
| `searchIncludes`, `searchExcludes` | Массивы подстрок: все includes должны встретиться хотя бы в одном поисковом поле; ни один excludes не должен встретиться. |
| `searchInJson` | Boolean: включить в поиск `kv`, `json_str`, `extra_json`. Может увеличить стоимость поиска. |
| `levels`, `excludeLevels` | Массивы уровней: `fatal`, `error`, `warn`, `info`, `debug`, `trace`, `unknown`. |
| `onlyErrors` | Boolean: только `error` и `fatal`. |
| `appSlugs`, `excludeAppSlugs` | Массивы точных slug плагинов. |
| `workspaceIds`, `excludeWorkspaceIds` | Массивы точных ID workspace. |
| `workspacePathPrefixes`, `excludeWorkspacePathPrefixes` | Массивы префиксов пути; используйте пути из найденных строк, обычно без `/` по краям. |
| `sources`, `excludeSources`, `logTypes`, `excludeLogTypes` | Массивы точных значений источников/типов; берите значения из найденных строк. |
| `traceId`, `userId` | Точное строковое значение ID. |
| `traceIdPrefix`, `url` | Строковый префикс trace либо подстрока URL. |
| `statusCodeMin`, `statusCodeMax` | Неотрицательные целые границы HTTP/handler status. |
| `responseTimeMinMs`, `responseTimeMaxMs` | Неотрицательные целые границы длительности в миллисекундах. |
| `onlyJobs`, `excludeJobs` | Boolean: непустой / пустой `job_id`. Не включайте оба одновременно. |
| `excludeWithoutWorkspace` | Boolean: убрать события без workspace. |
| `excludeApps` | Boolean: оставить события кода аккаунта с пустым `app_slug`. |
| `excludeUgcHandlers` | Boolean: убрать сообщения `UGC handler complete`. |
| `includesMap`, `excludesMap` | Объекты `{column: ["value"]}` для точного включения/исключения по разрешённым колонкам. |
| `orderDirection` | `desc` (по умолчанию) или `asc`. |
| `beforeTsMs` | Неотрицательное целое число миллисекунд; курсор «строго раньше», только для `desc`. |

Колонки для `includesMap` / `excludesMap`:

```text
level, app_slug, workspace_id, workspace_path, source, log_type,
user_id, trace_id, job_id, job_type, job_queue, method, error_type,
remote_address, handler_url, handler_method, entry_module_id,
entry_module_path, chatium_client, referer, account_host,
status_code, handler_status_code
```

В поиске по подстрокам/префиксам `%` и `_` имеют смысл wildcard: это не всегда
буквальный поиск. Для точных значений используйте подходящие точные фильтры.

Ограничения поиска:

- Окно до **24 часов**, конец не более чем на 60 секунд в будущем.
- `limit`: **1–500**, по умолчанию 50. Числовые фильтры — целые числа
  от 0 до `2^53 − 1`.
- Строка до 1000 символов, массив до 20 строк, map до 20 колонок,
  сериализованный JSON фильтров до 16 000 символов.
- До 30 чтений/мин на ключ, до 120/мин на аккаунт. После 429 уменьшите частоту;
  клиент не повторяет запросы автоматически.

### Примеры фильтров

В этих примерах клиент добавит текущее временное окно:

```json
{"onlyErrors":true,"workspacePathPrefixes":["orders"]}
{"searchIncludes":["payment","order-123"],"searchInJson":true}
{"traceId":"TRACE_ID_FROM_A_LOG_ROW","orderDirection":"asc"}
{"includesMap":{"job_id":["JOB_ID_FROM_A_LOG_ROW"]},"orderDirection":"asc"}
```

## Ответы и полнота

`list` возвращает `success`, `rows`, `hasMore`, `nextCursor`, `pageLimit` и
возможные дополнительные метаданные. `count` — `success`, `total`, `byLevel`;
он считает всё окно с фильтрами и игнорирует курсор. Имена полей строк обычно
используют snake_case, например `trace_id`, хотя фильтр называется `traceId`.

Клиент добавляет `client`: аккаунт, запрос, количество полученных/показанных строк,
`outputTruncated`, путь полного ответа. В stdout строки обрезаются до 2000
символов, суммарный JSON — до 30 000 символов. Нулевые значения сохраняются;
пустые поля могут быть убраны. `--output` сохраняет **исходный ответ одной
страницы** в новый файл `0600`; существующий файл не перезаписывается.
Размер ответа ограничен 32 MiB, сетевой таймаут — 45 секунд.

Для следующей страницы `desc` сохраните те же абсолютные `sinceMs`/`untilMs`
из `client.request.filters` и остальные фильтры. Преобразуйте
`nextCursor.ts64` (UTC) в миллисекунды Unix и передайте как `beforeTsMs`.
Не пересчитывайте окно относительно текущего времени между страницами.
Курсор использует строгое `<`, поэтому может пропустить оставшиеся события
с той же миллисекундой. `hasMore` означает заполненную страницу, а не
проверенное наличие следующего события. При плотном потоке сужайте окно и
фильтры; не заявляйте о полной выгрузке без проверки покрытия.

## Ошибки

| Симптом | Что проверить |
| --- | --- |
| 404 | Домен и доступность чтения логов в выбранном аккаунте. Если проблема сохраняется, обратитесь к администратору. |
| 401/403 | Выдан ли доступ, не отозван ли он, не истёк ли срок. Для формы — вход и роль Developer. |
| HTML или redirect | Доступность чтения логов. При повторении ошибки обратитесь к администратору. |
| `success: false` | Срок доступа, поля фильтров и окно. Это ошибка, а не пустая выборка. |
| 429 | Лимиты частоты; уменьшить число запросов. |
| Сетевая ошибка / timeout | HTTPS, DNS, прокси/VPN на машине, где работает Python. |
| Локально `active`, сервер отказал | Локальные метаданные не отражают отзыв. Отозвать/убрать старый доступ через `--logout`, затем запросить новый. |

Не обходите ограничения доступа. Пустые `rows` при
`success: true` означают отсутствие **доступных совпадений с текущими фильтрами**.
