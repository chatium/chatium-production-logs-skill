# Chatium Logs

Самостоятельный скилл для чтения и поиска платформенных логов `ctx.account.log`
из AI-агента или терминала. Python-клиент использует отдельный временный ключ,
выданный разработчиком аккаунта. Личная cookie не нужна.

## Что потребуется

- Python **3.9+**, macOS, Linux или WSL. Сторонних Python-пакетов нет.
- Доступ к Chatium-аккаунту с ролью **Developer** или выше для подтверждения.

## Быстрый старт

Клонируйте репозиторий и перейдите в его каталог:

```sh
git clone <URL-этого-репозитория> chatium-logs
cd chatium-logs
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru --login
```

Замените `ACCOUNT.chatium.ru` доменом аккаунта, **где выполняется ваш код**.

Клиент покажет ссылку и код `XXXX-XXXX`, затем откроет браузер. Войдите в аккаунт,
введите код, выберите **2, 6 или 12 часов** (по умолчанию 6) и нажмите
«Разрешить доступ». Не закрывайте терминал до подтверждения; код живёт 5 минут.
Если браузер находится на другом компьютере, добавьте `--no-browser` и откройте
напечатанную ссылку самостоятельно.

Проверка подтверждения идёт раз в 5 секунд. Она прекращается после выдачи
доступа, отказа, истечения запроса, ошибки или достижения лимита ожидания
в 5 минут. Начатый сетевой запрос может завершиться позже этого лимита.
Остановить ожидание вручную можно через `Ctrl+C`. После подключения фонового
опроса нет: каждая команда чтения выполняет один запрос.

```sh
# Последние 15 минут, максимум 50 строк.
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru

# Ошибки за час.
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru \
  --minutes 60 --filters '{"onlyErrors":true}'

# Поиск, включая структурированные JSON-поля.
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru \
  --filters '{"search":"order-123","searchInJson":true}'

# Количество событий в окне.
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru \
  --action count --minutes 60

# Статус локального ключа и отзыв доступа.
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru --auth-status
python3 scripts/read_logs.py --account ACCOUNT.chatium.ru --logout
```

`--help` показывает все параметры. Примеры фильтров и ограничения —
в [справочнике поиска](references/search.md).

## Использование агентом

Точка входа — [SKILL.md](SKILL.md). В ней есть весь рабочий процесс; файлы
репозитория не зависят от других скиллов или локальных инструкций автора.

Можно просто дать агенту путь к `SKILL.md` и задачу, например:

> Используй скилл chatium-logs из этого каталога. Найди ошибки за последние
> 30 минут в аккаунте ACCOUNT.chatium.ru и восстанови связанные trace.

Если ваша среда поддерживает каталог скиллов, скопируйте туда **всю папку
`chatium-logs`**, сохранив `scripts/` и `references/`. Место установки и способ
обнаружения зависят от среды: например, `~/.codex/skills/` для Codex и
`~/.claude/skills/` для Claude Code; вместо копии подойдёт символическая ссылка
на клон. Само клонирование ничего не подключает и не меняет настройки агента.
Скрипт также работает самостоятельно, без AI-агента.

Запросы идут с компьютера или сервера, **где запущен Python**, через его сеть,
VPN/прокси. Браузер нужен для выдачи разрешения. Локальный HTTP-сервис и фоновый
демон не требуются; агенту нужен терминал с HTTPS-доступом к домену аккаунта.

## Хранение и отзыв доступа

- Клиент создаёт отдельный случайный ключ и использует его для HTTPS-запросов
  после подтверждения доступа.
- Ключ хранится **без шифрования**, вне репозитория:
  `~/.config/chatium/logs/<host>.grant.json`, права `0600`.
  Не публикуйте этот файл и не передавайте его содержимое агенту через чат.
- Разрешение ограничено одним аккаунтом, чтением `list`/`count` и отзывом себя.
  Разрешение проверяется при каждом обращении. Ключ не привязан к IP.
- `--auth-status` проверяет локальные метаданные. Уже отозванное разрешение может
  выглядеть локально активным до следующего запроса к серверу.
- `--logout` подтверждает отзыв на сервере, затем удаляет секрет из локального
  файла. Если сеть недоступна, ключ сохраняется для повторной попытки.
- Доступ также можно отозвать через страницу управления разрешениями в аккаунте.
  После истечения срока чтение прекращается;
  клиент убирает истёкший ключ при следующем обращении к локальному состоянию.
- Логи тоже могут содержать секреты. `--output` сохраняет ответ с правами `0600`,
  но не обезличивает его. Сохраняйте такие файлы вне репозитория.

## Разработка и проверка

```sh
python3 -B scripts/test_read_logs.py
python3 -B scripts/read_logs.py --help
```

Тесты подменяют HTTPS, браузер, время ожидания и домашний каталог. Они не используют
реальные аккаунты, ключи и сеть. Проверяют выдачу, чтение, отзыв, истечение,
ограничение вывода, приватное хранение и остановку ожидания подтверждения.
Для проверки с реальными данными подключите свой аккаунт.

Для доработки меняйте `scripts/read_logs.py` и соответствующие проверки.
При изменении возможностей поиска обновляйте [references/search.md](references/search.md).
